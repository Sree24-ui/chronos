How one order is handled

Five structures, each doing one job.

CHRONOS-ADAPT · measured, not assumed

One index that picks its own shape.

Tree or array+bitmap for price levels, switched at a safe batch boundary with every order validated before the swap. These bars come from the benchmark files in results/, replayed on identical workloads.

Correctness first

Fast is worthless if it loses an order.

Strict price-time priority

Best price first, earliest order first at a price. Replacing an order gives it a new sequence number, so nobody can jump the queue.

Migration never moves an order

When the index switches shape, order nodes are not copied. Price order, FIFO order and totals are validated before the old index is dropped, with rollback on failure.

Checked against a slow oracle

Randomized command streams, including bad IDs and prices, run through every engine variant and a simple O(n) reference. Trades and book state must match exactly.
